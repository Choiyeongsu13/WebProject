이번에 고친 것 정리
====================

1. 글 삭제 / 수정 기능 (없던 것 새로 추가)
--------------------------------------
- ProfillDAO 에 postEditView / postUpdate / postDelete 세 메소드를 추가했습니다.
  postDelete 는 post 한 줄만 지웁니다. post_tag, post_comment 는
  테이블 만들 때 이미 ON DELETE CASCADE 로 걸어두셨기 때문에 자동으로 같이
  지워지고, album.post_id 는 ON DELETE SET NULL 이라 자동으로 비워집니다.
  (01_create_tables.sql 그대로 쓰신다면 손댈 것 없습니다.)

- 새 서비스 3개
    AdminEditService     : 글 수정 폼 (기존 글 값 채워서 write.jsp 로 보여줌)
    AdminEditProService   : 글 수정 처리
    AdminDeleteProService : 글 삭제 처리
  AdminController 에 cmd=admin_edit / admin_editpro / admin_deletepro 로
  연결해 두었고, 로그인 안 한 상태에서 주소를 직접 쳐도 admin_login 으로
  돌아가도록 needsLogin() 에 세 cmd 를 같이 넣었습니다.

- write.jsp 하나로 글쓰기/글수정을 같이 처리합니다.
  isEdit 값에 따라 폼 action, 제목, 저장 버튼 글자가 바뀝니다.
  수정 화면에서는 지금 등록된 대표 이미지를 먼저 보여주고,
  사진 칸을 비워두면 기존 사진이 그대로 남습니다.

- post.jsp 글 상세 화면에서, 로그인한 상태(sessionScope.loginUser)일 때만
  제목 아래에 [수정] [삭제] 가 뜹니다. 삭제는 confirm() 확인창을 한 번
  거칩니다. 로그아웃 상태면 주소를 직접 쳐도 AdminController 가 막습니다.


2. 사진(썸네일) 기능
--------------------
전에 쓰시던 cos.jar 의 MultipartRequest 는 실제로 프로젝트 안에
jar 가 없어서 컴파일 에러가 났던 것이었습니다. sample 프로젝트는
commons-fileupload2 를 쓰는데, 그것도 jar 를 3개(core / javax / commons-io)
더 넣어야 해서 또 같은 문제가 생길 수 있습니다.

그래서 이번에는 별도 jar 가 전혀 필요 없는 서블릿 자체 기능
(@MultipartConfig + request.getPart())으로 바꿨습니다. web.xml 이
Servlet 4.0 이라 바로 됩니다.

- AdminController 에 @MultipartConfig 를 붙였습니다.
- FileUploadUtil (새 파일) 이 업로드된 사진을 검사하고 저장합니다.
    · 확장자가 jpg/jpeg/png/gif/webp 가 아니면 저장하지 않습니다.
      (이게 없으면 이미지인 척하는 .jsp 파일을 올려서 서버를 공격할 수 있습니다)
    · 파일 이름은 System.currentTimeMillis() + 확장자로 새로 만듭니다.
      (같은 이름 파일이 덮어써지는 것을 막습니다)
    · 저장 위치는 webapp/images/posts/ 입니다. 폴더가 없으면 자동으로 만듭니다.
- AdminController 에 걸어둔 용량 제한 : 사진 1장 5MB, 전체 요청 10MB.


3. 글이 다른 메뉴 페이지에도 태그(분류)에 맞게 보이도록
--------------------------------------------------------
지금 구조에서 Works 는 project 테이블, Travel 은 album/photo 테이블을
따로 보여주고 있어서, Journal 에 쓴 글은 그 두 화면에 전혀 나타나지
않고 있었습니다. project/album 을 관리하는 화면까지 새로 만드는 것은
말씀하신 범위를 넘어서는 것 같아서, 대신 이렇게 연결했습니다.

- WorkListService 가 category 가 TECH 인 글 목록을 relatedPosts 로 같이 넘기고,
  projects.jsp 작업물 목록 아래에 "관련 글" 이라는 섹션으로 보여줍니다.
- TravelListService 가 category 가 TRAVEL 인 글 목록을 relatedPosts 로 넘기고,
  travel.jsp 앨범 목록 아래에 같은 방식으로 보여줍니다.
- 즉 글쓰기 화면에서 분류를 "기술" 로 선택해서 쓰면 Works 페이지 아래에,
  "여행" 으로 쓰면 Travel 페이지 아래에 그 글이 자동으로 나타납니다.
  (다만 이건 project_tag 에 쓰는 프로젝트 기술 스택 태그와는 다른,
   post_tag 에 붙이는 태그입니다 — 헷갈리지 않게 구분해서 만들었습니다.)

5. 그 밖에 같이 고친 것
------------------------
- .classpath 에 "C:/Users/컴퓨터/Downloads/ojdbc8.jar" 처럼 이 컴퓨터에만
  있는 절대경로가 하나 남아 있었습니다. 전에 겪으셨던 "전체가 안 뜨는" 문제의
  원인이었던 그 종류의 버그라 지웠습니다. ojdbc8.jar 는 WEB-INF/lib 안에
  이미 있어서 지워도 상관없습니다.

- DBManager.java 를 노트북 기준(오라클 23ai Free, 서비스명 FREEPDB1,
  profill 계정)으로 맞췄습니다. 비밀번호 칸만 본인 것으로 바꿔서 쓰세요.
    myURL  = jdbc:oracle:thin:@//localhost:1521/FREEPDB1
    myID   = profill
    myPass = "여기에_profill_계정_비밀번호를_적으세요"  <- 이 줄만 고치면 됩니다

- about.jsp 에서 쓰는 about.langs / about.backend / about.db / about.tools
  키가 message_ko.properties, message_ja.properties 양쪽에 빠져 있어서
  그 자리가 ???about.langs??? 처럼 나올 수 있었습니다. 추가했습니다.

- 자바 파일에는 설명 주석을 달지 않았고, 새로 만든 DAO/Controller/Service
  역할은 클래스 위에 한 줄로만 적어 두었습니다.
